<architecture>
- `RepoPromptCore` is the portable typed foundation. `RepoPromptSession`, `WorkspaceSessionStore`/`Router`, and actor `WorkspaceSelectionStateStore` own workspace roots, active session/tab, and explicit full/slice/codemap selection state. `FileSystemProviding`, path policy, slice types, and POSIX shims are also portable.
- `RepoPromptHeadless` owns validated workspace bootstrap and the actual read-only workspace behaviors. `HeadlessWorkspaceBootstrap` creates the session/store/router. `HeadlessToolCatalog` is a public in-process actor exposing tree, read, selection, search, local context build, and provider-backed Oracle calls, but its public call boundary uses MCP `Value` and `CallTool.Result`; its typed implementations and `HeadlessWorkspaceContextBuilder` are private/internal. `HeadlessOracleConfiguration` and workflow remain process-configured.
- `RepoPromptPortableCLI` demonstrates in-process composition: bootstrap a catalog once, retain shared selection state, call it directly, and normalize its JSON result. It does not spawn or speak stdio/MCP.
- Classic’s useful IDE shell is a two-column `NavigationSplitView`: workspace/file selection at left; task instructions, selected-context view, and copy/send action at right. The selected Classic references show only this workflow; rich editor, nested native file tree, presets, git/apply, multi-tab, AppKit, and agent-mode features are out of scope.
- CE’s selected root shell shows its current routing boundary, but it is an Apple SwiftUI reference only and must not enter the portable dependency graph.
- Current package has Swift tools 6.1, Swift language mode v5, two executable products, and a macOS platform declaration even though CI builds on Linux. Existing CI uses a pinned Swift 6.1 Jammy container; existing Docker packaging is deliberately headless.
</architecture>
