## Selection intent vs. selection behavior

| Concern | Stored intent | Implemented behavior |
| --- | --- | --- |
| Full files | `WorkspaceSelectionSnapshot.selectedPaths` | Complete (render + public API) |
| Slices | `.slices: [String: [LineRange]]` | Rendered per raw range; **no** `SliceRangeMath.normalize`, **no** `description` preservation, no CE clamp/merge; public API absent |
| Codemap-only | `.autoCodemapPaths` (misnamed; written only by `mode: .codemapOnly`, i.e. CE's `manualCodemapPaths`) | **None.** `HeadlessWorkspaceContextBuilder` emits `.autoCodemapUnsupported` ⇒ `isCompleteForProvider == false` ⇒ `PortableWorkspaceServiceError.incompleteContext` before HTTP |

`PortableWorkspaceService.applySelection` already implements internal `.get/.set/.add/.remove/.clear` × `.full/.slices/.codemapOnly` transitions, but they diverge from CE in three places (detailed in §3.2) and are not reachable from the public API (`addFiles/removeFiles/clearSelection` are full-file only). `PortableWorkspaceSelection` exposes `sliceFileCount`/`codemapFileCount` counts, never ranges or codemap file identities, so `RootShellView` can only toggle whole files.

## Two divergent CE envelopes — decision required and made

`AIMessage.fileTreeXML` wraps the *combined map* in `<file_tree>` and `fileBlocksXML` emits a trailing `"\n\n"` before `</file_contents>`, whereas `generateClipboardContent` and `AgentProviderContextBuilder` use `<file_map>` with `"\n\n"` joins. **Decision: portable adopts the `<file_map>` + `<file_contents>` fork/clipboard shape**, because (i) the task explicitly names `<file_map>`, (ii) portable renders no file tree so `<file_tree>` would be a lie, and (iii) `AgentProviderContextBuilder` is the exact structural analogue. The `AIMessage` divergence is recorded as a known CE inconsistency in the parity doc, not blended.

## Hard constraints discovered

1. **No `unsafeFlags` anywhere in the root manifest.** `LinuxDesktop` depends on the root package; SwiftPM refuses to build a package whose dependency uses `unsafeFlags`. All C targets must use only `cSettings: [.headerSearchPath, .define]`.
2. `package`-level symbols in `RepoPromptCore` (`SliceRangeMath`, new mutation helpers) are **not** visible to `LinuxDesktop`. The desktop must receive typed values through `RepoPromptHeadless` public models only — reinforced by `verify_linux_desktop_graph.py`, which asserts exact nested target dependencies.
3. Selection is **never persisted** (`WorkspaceSelectionStateStore` is in-memory; `--persist` only creates a state directory). There is no data migration surface.
4. `Package.resolved` must not churn (`AGENTS.md`); vendoring C sources instead of adding SPM dependencies keeps the root lockfile byte-identical.

# Design

## 3.1 Canonical packaging specification (normative)

New doc `docs/architecture/portable-selection-parity.md` holds this spec verbatim; the implementation is its only consumer.

### 3.1.1 Envelope

```
[<file_map> section]      ← present iff ≥1 codemap block was included
                          ← blank line separator only between present sections
[<file_contents> section] ← present iff ≥1 content block was included
```

- Section body = blocks joined with `"\n\n"`.
- Sections joined with `"\n\n"`.
- **Empty selection ⇒ `content == ""`.** The current header lines (`[RepoPrompt portable workspace context]`, `root[i]`, `[n root(s) omitted by byte budget]`, `No readable files are selected.`) are **removed** — they have no CE analogue and would break byte parity. Root identity already exists in `workspace_context.roots` (JSON) and in the Oracle workflow's `WORKSPACE_CONTEXT_INTEGRITY` block.
- `omittedRootCount` remains a field, is always `0`, and is documented as retained-for-compatibility.

### 3.1.2 Block ordering (placement)

1. `<file_map>`: manual codemap blocks in `manualCodemapPaths` insertion order, then automatic codemap blocks in expansion order (§3.4).
2. `<file_contents>`: one block per entry in deduplicated `selectedPaths` order; a path with non-empty normalized slices renders as a slice block, otherwise a full-file block.

This preserves the ordering asserted by `testDeterministicSelectionAndSliceOrdering` (slices-first when the sliced path precedes the full path in `selectedPaths`).

### 3.1.3 Path display policy

`CanonicalContextPackager.PathDisplay` — a two-case enum, no runtime switching:

- `.portableRootIndexed` (**production default**): `relative` for single root, `root[<n>]:<relative>` for multi-root. Preserves the existing MCP/CLI `display_path`/`entries[].path` contract *and* the Pro Edit system prompt's literal requirement to retain `root[n]:relative/path`.
- `.ceRelative` (**parity fixtures only**): `relative` for single root, `<rootLastComponent>/<relative>` for multi-root, absolute standardized path when two roots share a last component (CE's ambiguity rule).

Rationale for the deviation, recorded in the parity doc: block *structure* parity is provable independently of the path token, and switching production display would break the Pro Edit contract string that `RepoPromptHeadlessCatalogOracleTests` asserts.

### 3.1.4 Full-file and slice blocks

Ported literally from CE (§“Canonical CE specification”), with `fileName` taken from the path's last component for fence selection. Slice segments come from the new `SliceAssemblyBuilder` (§3.2.1), so labels reflect **merged, clamped** ranges and merged descriptions.

### 3.1.5 Codemap blocks

`CodeMapTextRenderer.render(_:displayPath:)` = `CodeMapAPIContentFormatter.pathAndImportsBlock(displayPath:imports:)` + `apiDescription`. `apiDescription` already begins and ends with `"\n"`, so a codemap block ends with a newline and the `"\n\n"` join yields one blank line plus that newline.

> **VERIFY:** the exact composition of CE's `CodeMapSyntaxArtifact.render(displayPath:)` (not in selected context). Validation: run the CE golden exporter (§3.9) and diff against `pathAndImportsBlock + apiDescription`; if CE inserts or trims a newline, adopt CE and update the spec.

Exactly-once rule: codemap blocks are keyed by resolved absolute path; a path present in both `selectedPaths` and `manualCodemapPaths` cannot occur (invariant (ii), §3.2.2), and automatic expansion skips any path already selected or manually codemapped.

### 3.1.6 Byte-budget algorithm

Inputs: candidate blocks with byte counts, `limit = maximumBytes`. Invariant: `content.utf8.count <= limit` always.

1. Build all candidate blocks (source reads bounded by `maximumSourceFileBytes` 8 MiB per file and `maximumAggregateSourceBytes` 64 MiB total, as today).
2. Partition candidates: `E` = explicit (manual codemap ∪ content), `A` = automatic codemap.
3. Reserve tag overhead for each section that has ≥1 candidate. Overhead = `"<file_map>\n" + "\n</file_map>"` and likewise for `<file_contents>`, plus one `"\n\n"` when both sections are present.
4. Greedy fill in this order: manual codemap blocks → content blocks → automatic codemap blocks. A block is included iff `used + separator + block ≤ limit - reservedOverhead`. Skipped blocks do not stop the loop (preserves `testBudgetSkipsOversizedEntriesAndContinuesWithoutReadingSparseFile`).
5. If a section ended up with zero included blocks, release its reserved overhead and re-run step 4 once. At most two re-runs (both → one → none). Deterministic, O(n).
6. Excluded **explicit** block ⇒ `omissions.append(.budgetExceeded)` and `truncated = true` (fail-closed, unchanged semantics). Excluded **automatic** block ⇒ automatic-codemap diagnostic only; never `truncated`, never an omission (§3.4.4).

Complexity: O(F) file reads + O(Σ ranges) assembly + O(B) assembly passes.

## 3.2 `RepoPromptCore` changes

### 3.2.1 New `RepoPromptCore/WorkspaceContext/Slices/SliceAssembly.swift`

Port CE's file with `package` access:

```swift
package struct WorkspaceSliceSegment: Equatable, Sendable { let range: LineRange; let text: String }
package struct WorkspaceSliceAssembly: Equatable, Sendable {
    let segments: [WorkspaceSliceSegment]
    let combinedText: String
    let totalLines: Int
    let detectedLineEnding: String
    let usedRanges: [LineRange]
    let isFullFile: Bool
}
package enum SliceAssemblyBuilder {
    package static func build(from content: String, ranges: [LineRange]?) -> WorkspaceSliceAssembly
}
```

CE's `String.splitContentPreservingAllLineEndings` / `splitContentPreservingLineEndings` are **not** in portable. Add `RepoPromptCore/WorkspaceContext/Slices/LineEndingSplitting.swift` with `package` helpers returning `[(line: String, ending: String)]` and the detected dominant ending, treating `\r\n` as one terminator, `\r` and `\n` as terminators, and a final line without a terminator as `ending == ""`. This replaces the builder's current `split(separator: "\n", omittingEmptySubsequences: false)`, which silently normalizes CRLF into content and is the root cause of CRLF parity failure.

### 3.2.2 `WorkspaceSelectionSnapshot` rename

`autoCodemapPaths` → `manualCodemapPaths` (its actual meaning; CE calls it that). `codemapAutoEnabled` keeps its name. No new stored field: automatic codemap paths are **derived at render time**, exactly as in CE.

Documented invariants, enforced by every mutation:

1. Every path with non-empty slices ∈ `selectedPaths`.
2. `manualCodemapPaths ∩ selectedPaths == ∅`.
3. All stored range arrays are `SliceRangeMath.normalize`d and non-empty; empty arrays are removed.
4. `selectedPaths` and `manualCodemapPaths` are deduplicated preserving insertion order.

Codable key stability is irrelevant (no persistence), but the MCP JSON key `auto_codemap_paths` is preserved by explicit mapping in the catalog (§3.5.3).

### 3.2.3 New `RepoPromptCore/WorkspaceContext/Selection/WorkspaceSelectionMutations.swift`

A `package enum` of pure, synchronous, non-throwing transitions on `inout WorkspaceSelectionSnapshot`, so the rules are testable without a session and shared by the service and any future consumer:

```swift
package enum WorkspaceSelectionMutations {
    package enum FullFileOperation { case set, add, remove, promote }
    package enum SliceOperation { case set, setPaths, add, remove }   // CE mutateSlices modes
    package enum CodemapOperation { case set, add, remove, demote }

    package static func applyFullFiles(_ s: inout WorkspaceSelectionSnapshot, paths: [String], operation: FullFileOperation)
    package static func applySlices(_ s: inout WorkspaceSelectionSnapshot, entries: [WorkspaceSliceEntry], operation: SliceOperation)
    package static func applyCodemapOnly(_ s: inout WorkspaceSelectionSnapshot, paths: [String], operation: CodemapOperation)
    package static func setAutomaticCodemapEnabled(_ s: inout WorkspaceSelectionSnapshot, _ enabled: Bool)
    package static func clear(_ s: inout WorkspaceSelectionSnapshot)
}
package struct WorkspaceSliceEntry: Sendable { let path: String; let ranges: [LineRange] }
```

**CE-parity rules, including three deliberate corrections to current portable behavior:**

| Operation | Rule | vs. today |
| --- | --- | --- |
| `set` full/slices | Replace `selectedPaths` (+ slices for the slice form); `codemapAutoEnabled` is **preserved**, not reset | today `.set/.full` builds a fresh snapshot, resetting `codemapAutoEnabled` to `true` — **fix** |
| `add` full | Append unique to `selectedPaths`; drop those paths from `manualCodemapPaths`; **preserve existing slices for those paths** | today deletes slices — **fix** (CE `addPaths` keeps `slices`; only `promote` clears them) |
| `promote` | Append to `selectedPaths`; drop from `manualCodemapPaths`; **clear slices** for those paths | new |
| `remove` (default/full) | Clear the path from `selectedPaths`, `slices`, **and** `manualCodemapPaths` | today's behavior, **retained** as an intentional deviation from CE `removePaths` (which keeps manual codemap entries), because portable `remove` is the UI/MCP "deselect" primitive and changing it would break existing callers. Recorded in the parity doc. |
| `remove` mode `codemap_only` | Clear only `manualCodemapPaths` entries | new, CE-faithful |
| `remove` mode `slices` | `SliceRangeMath.subtract`; empty `ranges` ⇒ remove all ranges for that path; a path whose ranges become empty stays in `selectedPaths` as a full file | new, CE-faithful |
| `set/add` codemap-only | Remove from `selectedPaths` and `slices`; append unique to `manualCodemapPaths`; set `codemapAutoEnabled = false` | today's behavior, retained |
| `demote` | Same as `add` codemap-only, but only for codemap-eligible extensions | new |
| slices `set` | Replace the whole `slices` map | new |
| slices `setPaths` | Upsert only the supplied paths, preserving other slices | today's `.set` with mode `.slices` replaces everything — clarified |
| slices `add` | `SliceRangeMath.coalesce` per path | new |
| all slice ops | After mutation, every path with non-empty ranges is appended to `selectedPaths` and removed from `manualCodemapPaths` | partially today |

Eligibility (`supportsCodemap`) is **not** decided here — it needs `RepoPromptCodeMap`. `applyCodemapOnly` accepts a pre-filtered path list; filtering happens in `PortableWorkspaceService` (§3.5.2).

### 3.2.4 Limit validation

`PortableWorkspaceService.validateSelectionLimits` moves into `WorkspaceSelectionMutations.validateLimits(_:) throws -> Void` returning a `package enum WorkspaceSelectionLimitViolation` (`tooManyPaths`, `sliceRangeCountOutOfRange`, `totalSliceRangesExceeded`), which the service maps to `PortableWorkspaceServiceError.invalidParameters` with the existing message strings (they are asserted by tests). Limits unchanged: 1024 paths, 1…256 ranges/file, 4096 total ranges.

### 3.3.2 Language matrix — declared v1 scope

**v1 supports Swift only.** CE's `supportsCodeMap` covers c/cpp/dart/go/java/js/php/py/rb/rs/swift/ts/tsx; each requires its own grammar, external scanner, query file, and extraction strategy, and byte-exact `definitionLine`/`L<n>:` parity must be proved per language with goldens. Shipping them together is not the smallest correct step and cannot be verified in one work item.

Consequence, faithful to CE rather than a fallback: a codemap request for a non-Swift file is **rejected at mutation time** with a `codemap_unavailable` entry — precisely what CE's `WorkspaceSelectionMutationService.supportsCodemap` + `WorkspaceBuildSelectionResult.codemapUnavailable` do for unsupported extensions. Nothing is silently omitted at render time, and no `auto_codemap_unsupported` omission survives.

Each additional language is a separate follow-up work item (grammar target + query + strategy + goldens) recorded in the parity doc's matrix table.

### 3.3.4 Extraction algorithm (Swift)

Inputs: UTF-8 `String`, language. Output: `CodeMapArtifactOutcome`.

1. Guard `utf8Bytes` and line count against `Limits` ⇒ `.oversize`.
2. Compute UTF-16 line boundaries with CE's exact rule (`\r`, `\n`, `\r\n` all terminate), so `L<n>:` numbers match CE.
3. `ts_parser_parse_string` ⇒ tree; nil tree/root ⇒ `.parseFailed`.
4. Execute the ported `Queries/swift.scm` capture set; iterate captures in byte order, maintaining the CE state machine: current class/enum boundary by line, containment checks via `rangeContains`, `definitionLine` = trimmed covering line(s), parameter/type formatting per CE's Swift strategy.
5. Finalize: keep classes/interfaces with ≥1 method or property, sort by first line, `referencedTypes` sorted+deduped, `definedTypeNames` = class ∪ interface ∪ alias ∪ enum names.
6. `hasMeaningfulContent == false` ⇒ `.readyNoSymbols`, else `.ready`.

Parity is validated by fixture-driven goldens (§3.9), not by re-deriving CE's internals from prose.

## 3.4 Automatic codemap expansion

Automatic mode is defined **separately** from manual codemap-only selection and is not redefined as manual mode.

### 3.4.1 Semantics

When `codemapAutoEnabled == true` and `selectedPaths` is non-empty, expand one hop: for each selected content file, resolve its `referencedTypes` to workspace files that *define* those type names, and include those files' codemap blocks in `<file_map>`. Files already in `selectedPaths` or `manualCodemapPaths` are skipped (exactly-once).

### 3.4.2 Components (`RepoPromptHeadless/Packaging/`)

```swift
struct CodeMapDefinitionIndex: Sendable {          // typeName → first defining absolute path
    static func build(candidates: [String],        // deterministic order (see 3.4.3)
                      artifacts: (String) -> CodeMapArtifactOutcome,
                      limits: Limits) -> (index: [String: String], candidateLimitReached: Bool)
}
struct AutomaticCodemapExpander: Sendable {
    struct Limits: Sendable { var candidateFiles = 4_096; var expandedFiles = 64 }
    struct Result: Sendable {
        var orderedPaths: [String]
        var excluded: [(path: String, reason: AutomaticCodemapExclusionReason)]
        var candidateLimitReached: Bool
        var expansionLimitReached: Bool

}
public enum AutomaticCodemapExclusionReason: String, Sendable {
    case languageUnsupported = "language_unsupported"
    case notFound = "not_found", oversize, parseFailed = "parse_failed"
    case noSymbols = "no_symbols", budgetExceeded = "budget_exceeded"
    case candidateLimitReached = "candidate_limit_reached"
    case expansionLimitReached = "expansion_limit_reached"

```

### 3.4.3 Determinism

- Candidates = `HeadlessWorkspacePathIndex.allFiles()` filtered to `CodeMapLanguage.supportedFileExtensions`, sorted by `.ceRelative`-independent absolute path (stable), truncated at `candidateFiles`.
- On duplicate `definedTypeNames`, the first candidate in that order wins.
- Expansion order: iterate `selectedPaths` in order; within each file iterate its `referencedTypes` (already sorted); append newly resolved paths; stop at `expandedFiles`.

All bounds are counts, never wall-clock, so goldens are reproducible. Fixtures are small enough that no bound binds.

### 3.4.4 Failure policy — the manual/automatic split

- **Manual** codemap-only paths are an explicit caller promise: `.languageUnsupported` is impossible (rejected at mutation), and `.notFound`/`.oversize`/`.parseFailed`/`.readyNoSymbols`/budget exclusion ⇒ `HeadlessWorkspaceContext.Omission` ⇒ `isCompleteForProvider == false` ⇒ existing fail-closed `incomplete_workspace_context`.
- **Automatic** expansion is *derived*: any exclusion is reported as a diagnostic and **never** produces an omission, `truncated`, or a provider block. Justification from CE: `PromptCanonicalCodemapPackagingTests` proves CE ships prompts with `coverage: .pending/.unavailable` and simply *omits* incomplete automatic codemaps rather than failing the request or falling back. Treating derived coverage as blocking would make a single unparseable dependency break every plan/review call.

`HeadlessWorkspaceContext.Omission.Reason.autoCodemapUnsupported` is **removed** (it can no longer be emitted). Removing an *output* enum value is not an input-schema change; it is covered by the software-version bump (§5).

## 3.7 Concurrency, lifecycle, caching

- All new mutations run inside the existing `PortableWorkspaceService` actor and mutate through `WorkspaceSelectionStateStore.mutate(for: nil, source: .headless)`, which is the single serialization point shared with `HeadlessToolCatalog`. Interleaved service/catalog mutations remain atomic (covered by the existing concurrency test; extend it to slice/codemap ops).
- **Artifact cache:** `PortableWorkspaceService` gains `private var codemapCache: [CodeMapCacheKey: CodeMapArtifactOutcome]`, key `(absolutePath, fileSize, modificationDate)`. Bounded at `HeadlessWorkspaceContextBuilder.maximumSelectionEntries` entries with insertion-order eviction (no LRU machinery). Cache is per-service-instance and never persisted.
- Extraction runs synchronously on the service actor. `Task.checkCancellation()` is called before each candidate parse and before each rendered block, so `previewContext`/`generatePlan` cancellation (already tested) also aborts index building. On cancellation the cache retains completed entries and the selection snapshot is unchanged — extraction has no side effects.
- Desktop calls remain `await`-from-`@MainActor`; long extraction blocks the service actor, not the GTK main loop. The `Cancel` button already cancels `currentTask`.
- `TreeSitterBridge` instances never cross concurrency domains: one is created and destroyed inside a single `extract` call. `CodeMapExtractor` is `Sendable` because it holds only value-typed limits.
- Out-of-order/duplicate completions: unchanged generation fencing in `DesktopState`; MCP calls are request-scoped and stateless beyond the shared selection store.

## 3.8 Error handling and edge cases

| Case | Behavior |
| --- | --- |
| Empty selection | `content == ""`, no sections, `isCompleteForProvider == true`, provider calls allowed (existing contract) |
| Slice on a file that becomes empty (0 lines) | `SliceAssemblyBuilder` yields no segments ⇒ `sliceOutOfBounds` omission (fail closed) |
| Range beyond EOF | Clamped per CE; a range starting past EOF is dropped ⇒ `sliceOutOfBounds` omission for that range only |
| Overlapping / adjacent ranges | Merged before storage (`SliceRangeMath.normalize`) and again in assembly; labels reflect merged ranges; descriptions joined `"; "` |
| CRLF source | Terminators preserved per line; slice text is byte-identical to the source substring |
| Non-UTF-8 source | `invalidUTF8` omission (unchanged) |
| Codemap on non-Swift file | Rejected at mutation with `codemap_unavailable`; selection unchanged for that path; `ok: true` |
| Manual codemap file unparseable / no symbols | `codemapParseFailed` / `codemapNoSymbols` omission ⇒ fail closed |
| Automatic dependency unparseable / missing / over budget | Diagnostic only; provider call proceeds |
| Path both selected and manual codemap | Impossible (invariant ii); `add .full` and `promote` drop the manual entry, `demote` drops the content entry |
| Symlink escaping a root | `symlinkEscape` omission via `HeadlessSecureFileReader` for both content and codemap sources; secret never enters `content` (extend the existing escaping-symlink test to a codemap selection) |
| Limits exceeded (1024 paths / 256 ranges / 4096 ranges) | `PortableWorkspaceServiceError.invalidParameters` with the existing messages, before any mutation is committed |
| Desktop slice text invalid | `sliceEditorError` set, no service call, selection untouched |
| Root removed mid-session | `notFound` omissions; `files()` returns fewer entries; no crash |

# 5. Risks and migration

1. **Rendered `content` changes for every existing MCP/CLI caller** (new envelope, no portable header/root lines, no “No readable files are selected.”). This is a success-semantics change ⇒ **`PortableContract.softwareVersion` 0.3.0 → 0.4.0**, documented in `portable-oracle-mcp.md`, with `ci.yml` and the release verifier updated together. maximum 4 concurrent parser tasks
```

If automatic mode is applicable and the candidate-file or aggregate-byte ceiling is exceeded, the context is incomplete with `codemap_index_limit_exceeded`; provider execution must fail before HTTP. Empty selection or selection containing no supported language is a complete, zero-automatic-codemap result and should not scan the entire workspace.

No cache should be introduced in the first implementation. A metadata-only cache risks stale artifacts under same-size/same-mtime replacement, while a secure content cache adds memory and invalidation complexity. The bounded per-render scan is the smallest correctness-first implementation; caching can be considered separately after profiling.

## 3.8 Context assembly algorithm

Refactor `HeadlessWorkspaceContextBuilder` into the one canonical assembler. Its `build` method becomes asynchronous and cancellation-aware.

Exact flow:

1. Receive an immutable `WorkspaceSelectionSnapshot` and byte ceiling.
2. Canonicalize stored paths and slice keys.
3. Apply full/slice/manual precedence and record invalid legacy state.
4. Resolve every explicit path through the shared path index.
5. Securely read selected full/slice source, enforcing per-file and aggregate limits.
6. Build strict full/slice blocks.
7. Parse selected supported source for automatic dependency analysis when enabled.
8. Resolve and render manual codemaps.
9. Resolve and render automatic codemaps.
10. Build the canonical selected file map.
11. Assemble complete `<file_map>` and `<file_contents>` sections.
12. Apply the final UTF-8 context budget only at whole-block boundaries.
13. Return metadata, omissions, resolved codemap identities, canonical content, and a deterministic selection manifest.

For complete contexts, `context.content` must be byte-for-byte canonical. Partial clarify output may contain only complete blocks; it must never cut a UTF-8 scalar, code fence, slice segment, codemap block, or XML-like section in half.

The aggregate 64 MiB source-read limit must apply to full files, slice files, and codemap candidates, not only slices.

## 3.13 Error and degraded-mode behavior

| Failure | Behavior |
|---|---|
| Invalid path/range/description | Mutation fails atomically; existing selection remains. |
| Missing selected path | Clarify/preview includes `not_found`; provider does not run. |
| Escaping symlink | No source read; omission and provider failure. |
| Unsupported manual codemap extension | Typed mutation rejects existing known files; persisted legacy state becomes `codemap_language_unsupported`. |
| Codemap parser failure/no symbols | Preview shows stable omission; no full-file fallback; provider does not run. |
| Auto index exceeds limits | Preview shows index-limit omission; provider does not run. |
| Ambiguous/unresolved automatic reference | No guessed path and no fallback; bounded diagnostic only if canonical CE behavior reports one. |
| Context byte limit | Only complete blocks are returned; `truncated` is true; provider does not run. |
| Provider failure | Existing lane-local error and Primary projection behavior remain. |
| Selection changes during provider execution | The pair completes against the original immutable context snapshot. |

# 5. Risks and migration

## 5.1 Persisted and API compatibility

There is no desktop persistence migration. `WorkspaceSelectionSnapshot` keeps the existing Codable fields, and automatic codemap results remain derived.

New public model fields and MCP JSON fields are additive. Existing fields retain their names and meanings, except that the legacy `auto_codemap_paths` name is explicitly documented as the stored manual codemap list it already represents.

Old binaries reading snapshots written by the new implementation see the same stored keys. New binaries reading old snapshots normalize them through `StoredSelectionPathNormalization` and precedence rules.

## 5.2 Prompt-semantic change

Replacing the portable-only renderer with canonical packaging is intentionally observable. Models may respond differently because:

- File boundaries change.
- Code fences are added.
- Slice descriptions become visible.
- Automatic codemaps may add structural information from files not explicitly selected as full content.

There must be no dual-renderer fallback. Byte-level goldens and provider capture tests are the regression boundary.

## 5.3 Automatic-codemap privacy and scope

`codemapAutoEnabled` defaults to true in existing snapshots. Once implemented, provider-backed calls may include source-derived API structure from dependencies that are not selected as full files.

Mitigations are mandatory:

- Preview shows every automatic codemap path.
- MCP output discloses derived paths.
- Provider manifest distinguishes editable selection from read-only codemap context.
- Only structural codemap text is sent; unselected full source is never sent.
- Desktop exposes an explicit automatic-codemap toggle.

## 5.4 Parser attack surface and performance

Tree-sitter introduces native parser code handling untrusted workspace source. Enforce file/count/aggregate limits, create parser instances per task, bound concurrency, and include malformed-input tests.

The first implementation deliberately performs bounded per-render indexing rather than introducing a potentially stale cache. Very large workspaces may produce `codemap_index_limit_exceeded`; that is preferable to silently incomplete automatic context.

## 5.5 Canonical behavior not present in selected evidence

The exact CE automatic dependency resolver and file-tree formatting implementation were not supplied. The plan resolves this with CE-side characterization fixtures before production coding. Do not infer or blend Classic and CE behavior.

CE is the canonical source. Classic can be used only to explain historical differences.

## 5.6 Version gate

This plan assumes the current `0.3.0` worktree is still pre-release, so `PortableContract.softwareVersion` and CI’s expected software version remain `0.3.0`.

Before merging, verify immutable tags/releases. If `0.3.0` has already been published, update all software-version references to `0.4.0` atomically. The tool schema remains `1.1.0` either way.

## 5.7 Uncommitted worktree protection

The implementation must be applied against the observed modified worktree, not a presumed clean branch.

Before touching files:

- Record `git status --short` and a patch of existing changes.
- Do not run `git reset --hard`, `git clean`, or broad checkout commands.
- Stage and commit by explicit path.
- Review each commit’s diff for unrelated file churn.
- Resolve root and nested package locks separately and revert unrelated pin changes.

## 5.8 Rollback

No data rollback is required. Reverting the feature code restores the previous renderer and unsupported-codemap behavior.

Existing released images and immutable tags are not modified. `latest` rollback rules remain unchanged.

# 6. Implementation order

1. **Protect and characterize the baseline.** Record the current dirty worktree. Verify whether software `0.3.0` is unpublished. In the CE repository, add characterization fixtures for automatic dependency resolution, file-map formatting, path display, and complete canonical packaging. This step changes no portable production code.

2. **Freeze dependency provenance.** Read the exact `SwiftTreeSitter` URL/revision and grammar revisions from the CE checkout. Add license/provenance records and the canonical fixture SHA-256 manifests.

3. **Add the codemap build graph atomically.** Add `RepoPromptTreeSitterLanguages`, `RepoPromptCodemap`, and `RepoPromptCodemapTests`; update root and nested lockfiles; update Docker build-stage source copies and graph verification. At this point both root executables and the existing desktop must compile, even if the new target is not yet used.

4. **Add the pure selection reducer.** Introduce `WorkspaceSelectionReducer`, the manual-codemap alias, public range/slice/mutation models, and service mutation APIs. Preserve existing service wrappers. Land reducer and mutation tests together.

5. **Add strict slice assembly and canonical packaging.** Port CR/LF/CRLF semantics and canonical full/slice wrappers. Add byte-level slice and packaging goldens before replacing the context builder.

6. **Implement codemap artifacts and rendering.** Add the 13-language generator surface, canonical artifact model, and renderer. Complete per-language artifact and text fixtures before automatic graph work.

7. **Implement automatic dependency resolution.** Build `PortableAutomaticCodemapResolver` to match the frozen CE characterization outputs. Add ambiguity, ordering, transitive-resolution, and exactly-once tests.

8. **Unify path resolution.** Extract the shared headless path index, add canonical prompt paths, and remove the duplicate private context-builder resolver. Re-run all symlink, multi-root, missing-path, and desktop-inventory tests.

9. **Replace the context assembler atomically.** Make `HeadlessWorkspaceContextBuilder` asynchronous, add manual/automatic codemaps, canonical file-map/content sections, whole-block budgeting, new omissions, and selection manifest data. Update service preview and fail-closed behavior in the same change. Do not leave the old renderer as an alternate path.

10. **Adapt the MCP catalog.** Add slice descriptions and `codemap_auto_enabled`, map to typed mutations, retain legacy JSON fields, and add detailed output. Keep seven tools and schema `1.1.0`. Land catalog schema and contract tests with this step.

11. **Update provider framing and typed review.** Add deterministic pair IDs for tests, the nonce-bound selection manifest, codemap read-only eligibility, generalized plan/review service methods, and complete captured-prompt goldens. Verify both lanes receive identical bytes.

12. **Extend the desktop state and controls.** Add the slice draft parser, focused-file mode controls, automatic toggle, review action, role markers, cancellation, and typed selection/result state. Land logic and service-integration tests before changing visual layout.

13. **Update Linux and container verification.** Extend graph checks, root/container codemap smoke, GTK Xvfb launch smoke, and release source policy. Confirm no GTK enters root headless binaries and no Apple framework enters the Linux compile graph.

14. **Update architecture and operating documentation.** Document canonical packaging, auto/manual semantics, privacy disclosure, runtime prerequisites, verification, non-goals, and the unchanged native-packaging boundary.

15. **Run the complete release-quality verification set.**
